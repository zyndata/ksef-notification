## Config flow wizard

| # | What it asks |
|---|---|
| 1 | **KSeF access** — environment, the company's NIP, the KSeF token. Verified against KSeF before it is accepted. |
| 2 | **Notification** — the phone to notify, and which invoice fields the message carries. |
| 3 | **Behaviour** — how often to check. |

Everything except the company's identity is editable later through the options flow.

## Selectable invoice fields

The user picks any subset. The candidate list below is the starting point; phase 1 finalizes the
list, the labels and the formatting.

"Source" matters: fields from the **metadata** cost nothing extra, while a field from the
**XML** means one more request per new invoice. The XML is fetched only when at least one
selected field needs it.

Sources verified against the official API on 2026-10-06; keys and paths, their cardinality and
which ones may be missing are documented in [KSEF_API.md](KSEF_API.md). Metadata keys are
fields of one `InvoiceMetadata` record; XML paths are relative to the root `Faktura` and are
matched by local name.

| Field | Source | Exact key or path | May be missing? | Notes |
|---|---|---|---|---|
| Seller name | metadata | `seller.name` | **yes** (nullable) | Fallback in the XML: `Podmiot1/DaneIdentyfikacyjne/Nazwa` |
| Seller NIP | metadata | `seller.nip` | no | |
| Invoice number | metadata | `invoiceNumber` | no | |
| Gross amount | metadata | `grossAmount` + `currency` | no | In the invoice currency |
| Net amount | metadata | `netAmount` + `currency` | no | In the invoice currency |
| VAT amount | metadata | `vatAmount` | no | **Always in PLN**, even when `currency` is not PLN |
| Issue date | metadata | `issueDate` | no | Date only |
| Invoice type | metadata | `invoiceType` | no | `Vat`, `Zal`, `Kor`, `Roz`, `Upr`, `KorZal`, `KorRoz`, `VatPef`, `VatPefSp`, `KorPef`, `VatRr`, `KorVatRr` |
| KSeF number | metadata | `ksefNumber` | no | The invoice's identifier in KSeF |
| Payment due date | XML | `Fa/Platnosc/TerminPlatnosci/Termin` | yes | Up to 100 due dates; FA(3) may give only a description (`TerminOpis`) |
| Payment form | XML | `Fa/Platnosc/FormaPlatnosci` (code 1–7), or `Fa/Platnosc/OpisPlatnosci` when `PlatnoscInna = 1` | yes | Direct child of `Platnosc` only — not the one inside `ZaplataCzesciowa` |
| Bank account | XML | `Fa/Platnosc/RachunekBankowy/NrRB` | yes | Up to 100 accounts; not `RachunekBankowyFaktora` |
| Line items | XML | `Fa/FaWiersz` (count), `Fa/FaWiersz/P_7` (description) | yes | TODO (phase 1): count, first few descriptions, or both. Correction "before" rows carry `StanPrzed = 1` |

XML fields exist only for FA(2) and FA(3) invoices; for PEF and FA_RR invoices they are treated
as missing.

Also in the metadata at no extra cost, not yet candidates: `acquisitionDate` (when KSeF assigned
the number — legally the date the invoice was received), `hasAttachment`, `isSelfInvoicing`,
`invoicingMode`.
